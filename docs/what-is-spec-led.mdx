Spec Led Dev is a simple way to write down what your code is supposed to do.

The spec lives in the repo, next to the code, so humans and AI can both use it.

It helps with common problems:

- code changes, but nobody updates the docs
- tests pass, but the code still drifts from the original intent
- new team members cannot get up to speed fast enough
- AI makes changes, but it is hard to tell if those changes fit the real contract

## The basic idea

You write short spec files for the important parts of a codebase.

Those specs say:

- what the code should do
- what should stay stable
- what tests or checks should prove it
- any approved exceptions

## What makes it useful

Because the spec is in the repo:

- humans can read it in GitHub and get up to speed faster
- AI has a clearer target when it writes or fixes code
- teams can see when the code has drifted from the intended behavior
- AI can help bring the code back in line when drift happens

## What it is good for

- packages
- modules
- APIs
- services
- workflows

It is meant to work in any language.
