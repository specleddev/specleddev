Write specs your AI can follow.

Put clear specs next to your code so humans and AI can see what the code is supposed to do.

## What problems does this solve?

Most software systems drift in predictable ways:

- AI can write code fast, but it often misses the point.
- Tests may pass, but the code can still drift from what you meant.
- Docs get old.
- New team members open GitHub and still cannot tell how the project is supposed to work.
- Important rules live in someone's head instead of in the repo.
- When the code drifts, there is no clear way to bring it back in line.

## What Spec Led Dev gives you

- A simple way to write down what a package, module, API, or workflow should do
- Spec files that live in GitHub with the code
- A clearer way for humans to get up to speed on the project
- A clear target for tests, docs, and AI changes
- A way to spot drift when the code no longer matches the intent
- A way for AI to help fix drift and bring the code back in line
- A format that works in any language

## How teams use it

- Write a short spec for each important part of the code
- Keep the spec in the repo
- Use the spec to help new team members understand the project faster
- Link the spec to tests, docs, and checks
- Use the spec to review changes
- Use the spec to guide AI when it writes or fixes code
- Use the spec to help AI correct code that has drifted from the original intent

## Built for humans and AI

Spec Led Dev helps humans get up to speed faster and helps AI make better changes.

It also gives AI a clear way to help fix code when the project starts to drift from what it is supposed to do.
