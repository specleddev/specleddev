Software changes faster than shared understanding among the people building it.

**That is the core problem.**

Spec Led Development helps teams document intent, build, and verify it as the code changes.

## The problem

When shared understanding slips, teams get:

- code that passes tests but still misses the point
- docs that go stale
- AI changes with weak context
- behavior that drifts over time

The rapid pace of development with LLMs has surfaced this problem in a new way.

## The solution

Spec Led Development follows a loop

1. Write your spec
2. Build code, tests, and docs from that spec with AI
3. Check your code against the spec on local and with CI

Humans stay in the loop. Specs keep the intent close to the code.

## Drift

> Drift is the gap between intent and reality.
>
> It happens when code changes but the spec, tests, and docs do not.
>
> The longer it stays hidden, the harder it is to fix.

Spec Led Development reduces drift by keeping the spec, code, tests, and CI in one loop.
